# ADR-001 — Game data out of the ROM: formats, layering, loader (2026-08-23)

Status: **accepted** (user, 2026-08-23); **phases 0-3 done the same day
(V392, commit "CUT-OVER")** — the game runs from `build/*.pak` with `rom/`
absent (selftest digest + shots identical, `strace` shows no `rom/` opens).
Remaining: rule 7 per-id slicing into the wrestler packages (the `ws_*`
tables in group `wrestler` are exported but still live in base.pak), rule 8
roster manifest / ids > 11, rule 6 schema doc, sound assets' provenance,
and a stricter reading of rule 4 for the big record blobs (`*_cell_records`,
`sprite_streams`, `move_policy` are honest spans, not named fields).
Supersedes nothing; constrains every future asset/table change.

## Decision in one paragraph

Everything the engine takes from the ROM today — tiles, palettes, pose
streams, tilemaps, and the ~300 runtime table reads — is exported **once** by a
C tool inside the engine binary (`wfengine --export-all`) into a
**human-readable source tree** (`data/`: JSON tables + indexed PNG sheets +
`.prov.json` provenance). A second C tool (`wfengine --pack`) flattens that
tree (base + mod layers) into **engine-native pak files** (`build/base.pak`,
`build/wrestlers/NN.pak`). The shipped runtime reads **only paks**; it never
opens `rom/`; there is **no ROM fallback**. The JSON/PNG tree is the source of
truth and the mod format; the paks are a regenerable cache.

## Why (see the discussion, 2026-08-23)

| | JSON + indexed PNG (source) | pak (runtime) |
|---|---|---|
| readable / diffable / editable | yes — the mod format | no — never hand-edited |
| schema tolerance | named fields survive struct churn | versioned header; regenerated by `build.sh` |
| integrity | per-file hashes in a manifest | one header + per-section CRC, one check at start |
| load | parsers (C JSON reader, PNG decoder) — used only by the packer | `fread`/`mmap`, zero parsing |
| mods | path overlay `mods/<name>/...` over `data/` | packer flattens layers; no runtime path resolution |

Hybrid = the readability/modding of the first column and the speed/integrity
of the second. The price is two readers (JSON/PNG in the packer, pak in the
engine) kept honest by the regress gate below.

## Rules

1. **C only.** Exporter, packer and loaders are `tools/*.c` / `src/*.c`
   driven by `wfengine --<verb>` (the project tooling rule). The exporter uses
   the engine's own decoders (`stream_decode.c`, `pal_load.c`, tile reader).
   A vendored single-header JSON reader and PNG codec are acceptable; Python
   never touches the pipeline.
2. **Exporter self-verifies before it writes**: decode from ROM → serialise →
   re-read through the packer's reader → compare byte-for-byte with the
   ROM-derived form. Mismatch = no file, non-zero exit. Every file carries a
   sibling `.prov.json` (ROM address, length, exporter `WF_VERSION`,
   `verified: true`) or, for sheets, a `manifest.json` with the same.
3. **Regress gate for every migration batch**: ROM build, JSON build (packer
   reading sources) and pak build must produce the **same `make regress`
   digest** and pixel-identical shots of the four drives. A table is "out of
   the ROM" only when its read site is gone from `src/` and the digest held.
4. **No hex in file names.** `mash_overlay_rows.json`, not `8a7e.json`; the
   ROM address lives in provenance only. Tables get names when they migrate.
5. **Indices, not RGB.** Sheets and tilesets are indexed PNG (pixel = palette
   index 0..15, 4bpp semantics preserved); palettes are JSON. Palette swaps,
   flashes, fades and the 0x2AEA body banks are gameplay and must keep working
   on indices. A modder recolours via the palette file or an indexed editor.
6. **Units are explicit.** JSON carries 16.16 fixed point as `{"fix": 0x12340}`
   or a documented integer with `_fix16` suffix; signed bytes as signed ints;
   bit flags as named booleans or a documented hex string. The schema
   (`docs/data-schema.md`, to be written with the first batch) is normative.
7. **If it is indexed by wrestler id, it lives in the wrestler package.**
   Global tables that today hold a row per id (portrait word `0x7814[id]`,
   name plate `0x816E[id]`, walk speed, `0xFDCC[id]`, `0xFDB4[id]`, announcer
   clip, 0x2AEA palette rows, select-grid slot, per-id move/AI rows, id×stage
   AI contexts) are sliced into `data/wrestlers/NN/`. `base` keeps only what is
   genuinely global (scenes, HUD/font tiles, banner glyphs, referee, rules,
   AI matrices keyed by category). Pair-keyed tables live with the *acting*
   wrestler, the other id as a column.
8. **The roster manifest is the authority on which ids exist.** Select screen,
   aisle, rumble pool, tag CPU fill iterate the manifest, not `0..11`; fixed
   `[12]` arrays and `% 12` go away as part of rule 7. Ids > 11 become legal.
9. **Layering**: `data/` is base; `mods/<name>/` mirrors its tree; a load-order
   list (`mods/order.txt`) decides precedence; the packer flattens. A package
   override is a whole `wrestlers/NN/` dir; a global override is per file.
10. **No ROM at runtime.** After the cut-over `wfengine` refuses to start
    without `build/base.pak` and the paks named by the roster; `rom/` is read
    only by `--export-all`. Until then the ROM path stays, but every new table
    read added to `src/` goes through the table layer, never raw `wf.rom[]`.
11. The exported tree is the copyrighted ROM content in another form: it
    stays in this private repo and is not shipped.

## Layout

```
data/                          # source of truth, in git
  manifest.json                # schema version, per-file sha256, roster list
  base/
    tables/<name>.json (+ .prov.json)      # global tables
    gfx/<set>.png + <set>.json             # tilesets, tilemaps, FG0 font, HUD tiles
    palettes/<bank>.json
    scenes/...
  wrestlers/NN/                # one package per wrestler (already: sheet.png,
    sheet.png tiles.json poses.json palette.json stats.json (+ per-id rows from rule 7)
mods/<name>/...                # same tree, overrides by path; mods/order.txt
build/base.pak, build/wrestlers/NN.pak    # generated by `wfengine --pack`, not committed
```

Pak format: magic `WFPK`, schema version, section table {name, offset, size,
crc32}, sections are the engine's own structs (native endian, fixed layout,
`static_assert` sizes). One pak per package; `base.pak` carries the roster and
the manifest hashes the packer saw.

## Loader API (engine side)

As built (src/tbl.h): `tbl8/16/32(TBL(name), off)` named reads and
`tbl_ra8/16/32(addr)` ROM-address-space reads (pointer-chased data keeps ROM
addresses as values; the registry maps an address to its table, disjoint
ranges enforced). Each source file declares the tables it owns with a
`static const tbl_def[]` + `TBL_REGISTER`. Backends: `tbl_load_pak` (the
game) and `tbl_load_rom` (tools / `WF_DATA=rom` reference). An address no
table covers reads 0 and is reported once (`tools/cov_drives.sh` = the
inventory; 0 at the cut-over). Packages: `package.c` reads
`build/wrestlers/NN.pak`; tile sets: `video.c` reads `build/gfx.pak`.

## Sequencing

0. Inventory (`docs/rom-reads.md`); delete the Python-era `data/romdata/`
   (unverified) — regenerate under rule 2 only.
1. Graphics: all sprite rows, tilesets/maps, FG0 font, palettes, scenes →
   `data/`; packer + pak reader; engine renders from the pak (ROM build kept
   for the regress comparison).
2. Tables: batches by subsystem (hud/banner → scenes → hit/moves → ai →
   anim), each through rule 3; per-id rows into packages (rule 7).
3. Cut-over: ROM loader compiled only into `--export-all`; rule 10 enforced.
4. Layering + roster manifest; ids > 11.
