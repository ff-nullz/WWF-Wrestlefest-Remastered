# Data pipeline — how the game's data gets out of the ROM and into the game

Decision record: `docs/adr-001-data-formats.md`. Migration brief:
`docs/table-migration-brief.md`. This page is the operator's view.

## Layout

```
rom/                          the ROM set (git-ignored) — read ONLY by the export/verify tools
data/tables/<group>/<name>.json   ROM tables, exported + verified (source of truth, moddable)
data/tables/manifest.json         schema version, per-file crc32
data/wrestlers/NN/                wrestler packages: sheet.png (indexed), tiles.json, poses.json,
                                  palette.json, stats.json (from `wfengine --export ID DIR`)
data/gfx-edit/                    fg0.png, tiles.png, sprites/sheet_NNNN.png — the tile sets
                                  (indexed PNG; `wfengine --verify-gfx` proves them against the chips)
mods/<name>/...                   same tree shape; mods/order.txt lists mods, later lines win
build/base.pak                    runtime tables      }
build/wrestlers/NN.pak            runtime packages    } generated by `wfengine --pack`, git-ignored
build/gfx.pak                     runtime tile sets   }
data/weapons/                     the weapon table: weapons.json (cells per carry pose, attach offsets,
                                  per-type palette/rules, spawn list), palette.json, <type>/overlay_NNNN.png
build/weapons.pak                 runtime weapon table (`--pack-weapons`, also by `--pack`); a profile whose
                                  mods carry weapons/ gets build/profiles/<p>/weapons.pak
```

## Commands

| command | what |
|---|---|
| `./wfengine --tables` | list every registered table (name, group, ROM addr, len, kind, stride) |
| `./wfengine --export-all data/tables` | ROM → JSON tree; each file re-read and compared before it is kept |
| `./wfengine --export ID data/wrestlers` | one wrestler package (poses/palette/stats/tiles/sheet) |
| `./wfengine --verify-gfx` | decode the gfx chips and compare with data/gfx-edit pen-for-pen |
| `./wfengine --pack data/tables build/base.pak` | JSON tree (+ mod layers) → base.pak, wrestlers/NN.pak, gfx.pak; every pak is re-opened and verified |
| `./wfengine --weapon-table data/weapons` | ROM poses → the weapon table (nibble-15 cells of the 18 carry/pickup/swing poses, attach offsets, palette = body entry 0x1C) |
| `./wfengine --pack-weapons data/weapons build/weapons.pak` | weapon table → pak (sections wtypes/wattach/wpal/wrules/wspawn; tools/pack_weapons.c) |
| `./wfengine --weapon-check` | every stock man × carry pose × facing: the pak's cells (+ attach, mirrored) == the ROM template's bank-15 cells |
| `tools/cov_drives.sh out.txt` | run the drive set; list every ROM read no table covers (transition) |

`./build.sh` runs `--pack` after `make`, so the paks always match the binary's
registered tables.

## Runtime selection

Default: the paks — `build/base.pak`, `build/wrestlers/NN.pak`,
`build/gfx.pak`; a missing pak is a clear error (`./build.sh` or `make pack`
regenerates them). `rom/` is never opened by the game. `WF_DATA=rom` is the
**reference mode** for the regress gate only: tables from the ROM image, the
JSON/PNG trees for packages and tiles — any read no table covers is then
reported once (`tbl: UNMAPPED ROM read at 0x..... from src/file.c:line`) and
`tools/cov_drives.sh` must stay at 0. `WF_PAK`, `WF_PAKDIR`, `WF_GFXPAK`
override the pak paths. Rules (engine scalars, group `rules`) are
synthetic tables with compiled defaults: edit `data/tables/rules/*.json`.

## Adding a table (engine side)

```c
#include "tbl.h"
static const tbl_def my_tables[] = {
    { "walk_angle_by_stick", "base/anim", 0xF2D6, 16, TK_U8, 16, "0xF292 walk angle by held nibble" },
};
TBL_REGISTER(my_tables)
...
unsigned ang = tbl8(TBL(walk_angle_by_stick), nib);
```
Rules: names without hex; groups by subsystem; per-wrestler rows in group
`wrestler`; tables disjoint and unique. `tbl_ra8/16/32(addr)` resolve a
ROM address through the registry (pointer-chased data). Then `./build.sh`,
`make regress` (digest must not move), `tools/cov_drives.sh`.

## Modding (today)

Edit `data/tables/<group>/<name>.json` rows (or copy the file under
`mods/<name>/<group>/` and list the mod in `mods/order.txt`), edit a
wrestler's `palette.json` / `sheet.png` / `stats.json` likewise, then
`./wfengine --pack data/tables build/base.pak`. The packer reports each
table whose bytes differ from the export-time crc as "modified".

## Extended wrestler ids: clone slots 12..15 (ADR rule 8, first cut)

A mod layer can add up to four wrestlers as CLONES of a stock one:

    mods/<m>/wrestlers/NN/wrestler.json   NN = 12..15
        { "clone_of": B, "name": "..." }  B = stock id 0..11
    mods/<m>/wrestlers/NN/palette.json    optional - else the base's
    mods/<m>/wrestlers/NN/stats.json      optional - else the base's
    mods/<m>/wrestlers/NN/{tiles,sheet,poses}  optional, own-layer only

`--pack-profile` packs `build/profiles/<p>/wrestlers/NN.pak` with a small
"clone" meta section (u16 base + name); palette/stats fall back to the
base's files at pack time, sheet/poses are packed only when the clone's
own layer provides them (the runtime delegates a missing section to the
base's pak — `src/package.c`). Loading the pak registers the clone;
`eng_ws_base(id)` (engine.h) then routes EVERY ROM-table index (moves,
speeds, AI rolls, portraits, throw matrices, announcer, banner plates)
through the base id, while `eng_pkg_*` answer from the clone's package
first. Sprites: the clone rides a virtual emit row (0x60+slot — stream
rows 12..15 are the referee/hardware) and BORROWS a free stock palette
bank for its pens (`sprite.c clone_bank_get`; banks 12..15 belong to the
referee/hw palettes).

Reaching a clone: the select screen does not offer ids 12..15 yet, so the
harness poke `WF_CLONE=NN` seats the CPU leader (slot 2) as that id.
Example: profile `clones` (mod `mods/clones`, id 12 "HOLLYWOOD" = blue
re-palette Hogan, hp 130):

    ./wfengine --pack-profile clones
    WF_CLONE=12 WF_CPU2=1 WF_NOINTRO=1 ./wfengine --profile clones \
        --headless --no-front --drive demo --frames 600 --shot out.ppm

Known limits (TODO EXACT): name plates/announcer use the BASE id (custom
name rendering needs the FG0 glyph runs); in a grapple between a clone
and its own base both figures bake palette id B, so the two-man cell
draws in one bank; rumble pick pools stay 0..11.
